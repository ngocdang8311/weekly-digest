# Weekly AI & Tooling Digest — 2026-W22

*Week of May 18–25, 2026*

## 🔴 Critical

### [Code with Claude London — Managed Agent Sandboxes & MCP Tunnels](https://claude.com/code-with-claude/london)
Anthropic's first European developer conference (London, May 19) shipped two infrastructure-level features for Claude Managed Agents: private sandboxes that run agents on a company's own infrastructure rather than Anthropic's cloud, and MCP tunnels that route agents to internal systems without exposing those systems to the public internet. Multiagent Orchestration and Outcomes moved to public beta; Dreaming (cross-session agent memory) remains in research preview with waitlist access. Claude Code rate limits were doubled for Pro, Max, and Enterprise subscribers.
**Why it matters:** MCP tunnels directly solve the "my internal tools are behind a firewall" problem — you can now build Claude agents that hit your own databases, internal APIs, or self-hosted git without routing anything through Anthropic's cloud.

---

### [Claude Code v2.1.149 — /usage Cost Breakdown, GFM Checkboxes, Enterprise MCP Setting](https://github.com/anthropics/claude-code/releases)
Released May 22, this build adds a per-category cost breakdown to `/usage` (skills, subagents, plugins, MCP-server spend), keyboard scrolling in the `/diff` detail view, and proper rendering of GFM task-list checkboxes (`- [ ]` / `- [x]`) in Markdown output. The enterprise `allowAllClaudeAiMcps` managed setting controls which claude.ai cloud MCP connectors are available org-wide. Fixed: PowerShell permission bypass via built-in `cd`, sandbox write-allowlist failures in git worktrees, and `find` exhausting macOS resources on large trees.
**Why it matters:** The `/usage` breakdown finally makes it possible to see which part of your agent stack is burning tokens — essential for cost-managing multi-agent workflows using skills, subagents, and MCP servers together. The git-worktree sandbox fix matters if you use `claude ultrareview` or worktree-based parallel agents.

---

### [Gemini CLI v0.43.0 Stable (May 22)](https://github.com/google-gemini/gemini-cli/releases)
The stable release steers Gemini models to prefer the `edit` tool for surgical code changes rather than full-file rewrites, adds session portability (export an active session to a file, resume it later via CLI flag), and ships an adaptive token calculator for more accurate context-window usage. UI rendering is fixed via native ToolDisplay properties. The preview track (v0.44.0-preview.0, May 22) unifies all Auto modes into one and adds Sublime Text and Emacs Client support.
**Why it matters:** Session portability closes a gap with Claude Code's `/resume` — you can now hand a Gemini CLI session to a teammate or CI job. The edit-tool steering should reduce the "Gemini rewrote my whole file" problem that made it less practical for incremental work.

---

### [Codex CLI 0.132.0 & 0.133.0 — Goals Default On, Python SDK Auth, Remote-Control](https://github.com/openai/codex/releases)
0.132.0 (May 20) ships a revamped Python SDK with first-class authentication — API key login, ChatGPT device-code flow, account inspection, and logout APIs — plus simpler text-only `TurnResult` objects. 0.133.0 (May 21) enables Goals by default with dedicated storage, expands permission profiles with list APIs and inheritance, and adds lifecycle hooks for subagent start/stop and tool execution to the plugin API.
**Why it matters:** Goals-by-default means Codex now persists task intent across tool calls without manual setup — a catch-up to Claude Code's `/goal` behavior. The Python SDK auth improvements make it straightforward to build server-side Codex integrations without managing credentials manually.

## 🟡 Noteworthy

### [Cloudflare — Wrangler Tunnel for Local Dev, wrangler dev --remote Flag Removed](https://blog.cloudflare.com/)
Cloudflare Tunnel now supports sharing local Wrangler and Cloudflare Vite plugin dev sessions as public URLs — useful for webhook testing and cross-device previews without a full deployment. Separately, support for the legacy `wrangler dev --remote` flag for KV-backed Durable Objects was removed on May 18 as part of the ongoing consolidation of Pages into the Workers platform.
**Why it matters:** The tunnel shortcut removes the ngrok dependency for Workers webhook development. If any of your Cloudflare KV + Durable Objects tooling still used `--remote`, it will silently break after May 18 — worth auditing your `wrangler.toml` configs and CI scripts.

### [WooCommerce Subscriptions Auth Bypass — CVE-2026-1926 (Critical)](https://www.sentinelone.com/vulnerability-database/cve-2026-1926/)
The Subscriptions for WooCommerce plugin (≤ 1.9.2) has a missing capability check that allows any unauthenticated attacker to cancel any active subscription on the site, no account required. The May 2026 WooCommerce CVE count is up 4% month-over-month, with authentication/authorization failures dominating the high-severity list.
**Why it matters:** If Bucktee or any adjacent plugin touches WooCommerce subscription state, check whether you rely on the subscription status as a gate — an attacker could cancel subscriptions to downgrade access or trigger refund workflows before you patch.

## 🧠 Takeaways

- **The pivot to private agent infra is real.** Anthropic's Code with Claude London made the case explicitly: sandboxes on your own infrastructure plus MCP tunnels to internal systems is the architecture required before enterprises will put Claude agents on sensitive workflows. This is less a product feature and more a deployment-model shift.
- **All three CLIs shipped in the same week, and the gap is closing.** Gemini CLI's session portability and Codex's goals-by-default both mirror Claude Code features that landed weeks earlier. Claude Code's Managed Agents runtime is still the only production-grade hosted option, but the tooling baseline is converging fast.
- **Cloudflare's "Pages is now Workers" migration is done in all but name.** The `--remote` flag removal is a signal: new Cloudflare primitives (Dynamic Workers, Sandboxes, AI Gateway) are Workers-only. If your stack still uses Pages-specific mental models, the platform has moved on.
- **WooCommerce auth/authz bugs keep coming.** CVE-2026-1926 is the third WooCommerce-adjacent unauth privilege escalation in two months. The pattern is consistent: AJAX handlers or REST endpoints that check nonces but skip capability checks. Worth running a targeted audit of any custom plugin endpoints that modify order or subscription state.
