## 🔴 Critical

### [Claude Code v2.1.232: Subagent Forking On by Default + Cross-Session @Mentions](https://github.com/anthropics/claude-code/releases/tag/v2.1.232)
Subagent forking now ships enabled by default, meaning a `subagent_type: "fork"` agent inherits the full conversation and prompt cache rather than starting cold. The same release adds `@mention` support: type `@` in a prompt to reference another live Claude session by name, and `SendMessage` routes there directly. Also fixed: a PowerShell permission bypass, a Windows Git Bash symlink validation gap, and nested git repositories inheriting workspace trust from a parent directory.
**Why it matters:** If you're running multi-agent workflows in Claude Code (common for Bucktee plugin tasks or Cloudflare Workers scaffolding), forked subagents now share your existing context cache — fewer cold starts, lower token cost on split tasks. The @mention feature opens genuine multi-session orchestration without scripting it yourself.

### [Claude Code v2.1.233: Task/Todo Tools Removed from Sonnet 5+, GitLab Worktree Support](https://github.com/anthropics/claude-code/releases/tag/v2.1.233)
The built-in `Task` and `Todo` tools are removed for Opus 4.8, Sonnet 5, and all newer models; earlier models are unaffected for now. Also added: GitLab merge request URL support in the `--worktree` flag and `claude agents` view, an opt-in `forward_user_identity` gateway setting for user attribution, memory cgroup support for Bash tool commands on Linux via `CLAUDE_CODE_TOOL_MEMORY_LIMIT`, and a `CLAUDE_CODE_WEBFETCH_CACHE_TTL_MS` env variable for WebFetch cache tuning.
**Why it matters:** Any CLAUDE.md instructions, hooks, or workflow scripts that invoke `TaskCreate`/`TaskUpdate`/`TaskList` will silently get nothing on Sonnet 5+ — audit and migrate these to native agent patterns before relying on them in production sessions. The GitLab worktree support broadens Claude Code's reach beyond GitHub-only shops.

### [Claude Sonnet 5 Pricing Made Permanent at $2/$10 per Mtok](https://www.anthropic.com/news/claude-sonnet-5)
The promotional introductory pricing for Claude Sonnet 5 — $2/M input tokens, $10/M output tokens — was made permanent on August 10, 2026, rather than expiring August 31 as originally announced. Sonnet 5 also carries a native 1M-token context window.
**Why it matters:** Sonnet 5 is already the default model in Claude Code (since v2.1.197); the pricing lock-in means your daily Claude Code usage costs are now stable and predictably lower than Opus 5 ($5/$25) for the vast majority of coding tasks — good signal to stop treating Sonnet 5 as a temporary budget option in your tooling configs.

### [Cloudflare: Access Now Attaches to Workers Directly, Not Routes](https://developers.cloudflare.com/changelog/post/2026-08-14-workers-access/)
Cloudflare Access policies can now be attached to the Worker itself rather than configured per-route or per-domain. Every associated domain, custom domain, and preview URL inherits protection automatically when routes change. A new account-wide toggle makes all Workers private by default — new and existing — with per-Worker bypasses to keep public-facing ones accessible. `ctx.access.getIdentity()` returns user email, name, and groups without manual JWT validation. Local testing works via a `dev` block in `wrangler.jsonc`.
**Why it matters:** If you're shipping internal tools or admin APIs on Cloudflare Workers (e.g., Bucktee plugin webhook endpoints, private dashboard routes), this removes the per-route Access configuration burden and closes the "forgot to protect the preview URL" gap. The local dev testing support is particularly useful for iterating on access-controlled Workers.

### [Codex CLI 0.148.0-alpha: /import from Claude Code and Cursor](https://github.com/openai/codex/releases)
OpenAI's Codex CLI published a rapid series of pre-release versions (0.148.0-alpha.11 through 0.148.0-alpha.20, August 13–16). The headline feature is `/import`, which lets users migrate setup context and recent chat history from Claude Code or Cursor into a local Codex CLI session, lowering the switching cost between AI coding tools.
**Why it matters:** OpenAI is explicitly targeting Claude Code's installed base with migration tooling — worth a test run if you want a second agent for tasks where Codex's sandboxed execution model fits better, without re-configuring your project context from scratch.

### [Gemini CLI Deprecated for Free/Pro/Ultra — Google Unifies Under "Antigravity CLI"](https://developers.googleblog.com/an-important-update-transitioning-gemini-cli-to-antigravity-cli/)
Since June 18, 2026, Gemini CLI stopped serving requests for Google AI Pro, Ultra, and free-tier users. Google has rolled CLI tooling into a single multi-agent platform called Antigravity, with Antigravity CLI as the successor. Gemini CLI itself remains technically accessible via paid Gemini Enterprise Agent Platform API keys. The latest nightly build is v0.56.0-nightly (August 10).
**Why it matters:** If any scripts or automation in your stack invoke `gemini` CLI directly, they may be silently failing for free/Pro users. Check your Gemini CLI usage tier before the next deployment; Antigravity CLI is the path forward and warrants evaluation for parity on features you rely on.

## 🟡 Noteworthy

### [WooCommerce < 10.5.3: CSRF Allows Unauthenticated Admin Account Creation (CVE-2026-3589)](https://patchstack.com/database/wordpress/plugin/woocommerce/vulnerability/wordpress-woocommerce-plugin-10-5-3-arbitrary-admin-user-creation-via-csrf-vulnerability)
A CSRF vulnerability in WooCommerce 5.4.0–10.5.2 allows an unauthenticated attacker to create arbitrary administrator accounts if a logged-in admin visits a crafted page. The flaw is in insufficient token validation on batch API requests, which can be proxied through the admin's active session. Fixed in WooCommerce 10.5.3.
**Why it matters:** Bucktee plugin installs live alongside WooCommerce; if any Bucktee user's site is still on WooCommerce ≤10.5.2, admin takeover is a realistic attack path — consider an in-plugin update nag or compatibility check targeting this version floor.

## 🧠 Takeaways

- **Anthropic is betting on persistent multi-agent sessions as the primitive**: forked subagents by default, @mention cross-session messaging, and cross-machine `SendMessage` all shipped within a week. This isn't incremental polish — it's a new usage model where a single project spawns a mesh of named, stateful agents. Design your next Claude Code workflows with this in mind.
- **The Task/Todo tool removal from Sonnet 5+ is the sleeper breaking change**: it produces no error, just silence. Any automation, hook, or CLAUDE.md instruction that depended on these tools should be audited now rather than after a confused debugging session on a Friday.
- **Cloudflare's Worker-level Access is the right approach, finally**: the old per-route model was a configuration debt trap — a new route meant an unprotected URL until someone noticed. Attaching policy to the Worker itself and making private-by-default an account toggle is how zero-trust should work. Roll this out on any internal Workers you're running.
- **Google's "Antigravity" rebrand is strategically muddled, tactically painful**: swapping out a product name without surfacing why or where the name comes from, while leaving the old CLI technically alive for enterprise API users, is the kind of half-migration that breaks CI pipelines quietly. Keep Gemini CLI pinned in any scripts until Antigravity CLI has stable release cadence parity.
