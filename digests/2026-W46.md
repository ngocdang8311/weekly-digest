# Weekly AI & Tooling Digest — 2026-W46

*Week of 2026-11-03 to 2026-11-09*

## 🔴 Critical

### [Claude Code v2.1.317–2.1.319 (Nov 3–6)](https://code.claude.com/docs/en/changelog)
Three releases shipped this week. v2.1.317 adds `onFailure: "block"` for Agent SDK hook callbacks and a guard that prompts before a web/shell tool sends your account email. v2.1.318 surfaces login-expiry warnings in `claude auth status` and `claude -p` JSON. v2.1.319 introduces **MCP tasks in the terminal** (run in the background, report when done), `permissions.denyInsteadOfPrompting`, and `/claude-api latency-optimize`.

**Why it matters:** `onFailure: "block"` on hooks is directly relevant to any scheduled task or Bucktee plugin integration that uses the Agent SDK — a failed webhook no longer silently passes through. MCP background tasks change how long-running tool calls behave in automated `/loop` sessions.

---

### [Auto Mode Behavior Change Behind Gateways (v2.1.319)](https://code.claude.com/docs/en/changelog)
Auto mode without telemetry or feature flags now asks or denies instead of falling back to the built-in classifier. This affects any Claude apps gateway deployment with telemetry disabled.

**Why it matters:** If you run Claude Code behind a Cloudflare AI Gateway or any LLM proxy with telemetry off, auto mode's fallback has changed. Set `CLAUDE_CODE_AUTO_MODE_SERVER=0` to restore previous behavior before the November 30 Opus 4.8 fast-mode removal.

---

### [Opus 4.8 Fast Mode Deprecated — Removal November 30](https://code.claude.com/docs/en/changelog)
Fast mode for Opus 4.8 was deprecated October 30 and will be removed November 30, 2026. Anthropic points to Opus 5.5 as the replacement.

**Why it matters:** Any workflow or automation hardcoded to Opus 4.8 fast mode has three weeks to migrate to Opus 5.5; Claude Sonnet 4.5 is also retiring November 30 per the deprecation docs.

---

### [Codex CLI v0.167.0 Released (Nov 6)](https://github.com/openai/codex/releases)
The latest stable release ships an **agent command center** (`codex agents --no-daemon`), backend switching from the session picker without losing drafts, local image previews in supported terminals, and a GCP Vertex AI setup wizard (`gcp_setup_wizard` flag). Alpha work on v0.168/0.169 is ongoing daily.

**Why it matters:** Backend switching means you can compare Claude and other providers mid-session in Codex without restarting — useful for benchmarking on TypeScript/Next.js tasks where you rely on both Codex and Claude Code daily.

---

### [Gemini CLI v0.67.0 Stable + v0.68.0 Preview (Nov 4)](https://github.com/google-gemini/gemini-cli/releases)
v0.67.0 adds a `models` command to list available models and fixes a hook timeout that had migrated with a 1000x too-small value. v0.68.0-preview.0 was also tagged the same day, continuing the weekly stable/preview cadence.

**Why it matters:** The hook timeout fix is directly relevant if you share hook scripts between Gemini CLI and Claude Code sessions — the previous miscalibrated timeout would silently kill long-running hooks.

## 🟡 Noteworthy

### [Cloudflare Workers: New JS Module Registry Default (Nov 17 compat date)](https://developers.cloudflare.com/workers/platform/changelog/)
Starting with compatibility date November 17, 2026, the new JavaScript module registry becomes the default, and client-disconnection events become available without an explicit opt-in flag.

**Why it matters:** Workers on Cloudflare Pages that upgrade their compat date to `2026-11-17` will gain automatic client-disconnect detection — useful for cleaning up KV writes or Durable Object sessions when users navigate away. Worth testing before auto-upgrading.

---

### [Critical WooCommerce Plugin CVEs: Unauthenticated Privilege Escalation](https://www.strix.ai/cve/CVE-2026-119075)
Two critical CVSS 9.8 flaws disclosed this week: **CVE-2026-100109** (Security For WooCommerce ≤1.0.16 — unauthenticated admin account creation) and **CVE-2026-119075** (Registration Form for WooCommerce ≤1.1.4 — role parameter manipulation at checkout escalates to admin). Both are unpatched at time of disclosure based on available reports.

**Why it matters:** If the Bucktee plugin or any adjacent WooCommerce extension ships a registration or security add-on, audit whether these plugins are in your dependency tree. Admin creation without authentication is a full site takeover risk.

### [SpaceX Acquisition of Cursor Closed (Aug 2026) — OpenAI Model Supply Ending ~Nov 12](https://en.wikipedia.org/wiki/Cursor_(company))
Unconfirmed reports from a single source indicate OpenAI plans to stop supplying models to Cursor around November 12 as a consequence of its SpaceX acquisition. Cursor's Composer 2 was already built on Kimi 2.5 (Moonshot AI), suggesting the pivot away from OpenAI models pre-dates any supply cut.

**Why it matters:** If confirmed, Cursor's model choices will narrow to non-OpenAI backends. As someone whose primary tool is Claude Code, this is mostly competitive context, but it may accelerate teams stuck on Cursor to evaluate Claude Code. Treat the November 12 date as rumored until primary reporting confirms.

## 🧠 Takeaways

- **Claude Code is shipping fast and changing defaults.** Three releases in four days touched gateway behavior, hook semantics, and the `/loop` self-pacing model. If you run any automation against Claude Code — scheduled digests, CI agents, Bucktee webhook processors — re-read the v2.1.317–319 changelog before November 30 when two more deprecations land.
- **The November 30 deadline is real.** Both Opus 4.8 fast mode and Sonnet 4.5 retire on the same day. If any of your projects hardcode a model string, audit now.
- **WooCommerce continues to be a high-value attack surface.** Two critical unauthenticated privilege-escalation flaws in the same week, both in widely-used registration/security plugins. The pattern (missing authorization on user-creation endpoints) is well-known and should be part of any Bucktee plugin security checklist.
- **Cloudflare's client-disconnect event (compat date Nov 17) is underappreciated.** Workers currently keep running after a client disconnects — paying for compute with no recipient. Opting in early on dev/staging is low-risk and surfaces real savings on KV-heavy Workers routes.
