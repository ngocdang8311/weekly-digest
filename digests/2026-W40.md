# Weekly AI & Tooling Digest — 2026-W40

*Week of 2026-09-21 to 2026-09-28*

## 🔴 Critical

### [Claude Opus 5.5 Released — Now Default in Claude Code](https://www.anthropic.com/news/claude-sonnet-5)
Claude Opus 5.5 shipped on September 22 as the new default Opus model across Claude Code and the API. It brings a 1M-token context window, $4/$20 per Mtok pricing (40% cheaper than its predecessor), and leads benchmarks in agentic coding and computer use. Sonnet 5.5 and Haiku 5.5 are announced as arriving "in the coming weeks."
**Why it matters:** Claude Code auto mode now defaults to Opus 5.5 on Pro/Team Standard tiers, so your agentic workflows get a better model at lower cost with no config change required.

### [Claude Code v2.1.283 — Team Model Locking + Prompt Audit](https://code.claude.com/docs/en/changelog)
Three releases this week (v2.1.281–283) shipped notable capabilities: `availableModelsMatch`/`deniedModels` managed settings to lock or block specific model versions org-wide; a new `/doctor prompt-audit` command to detect stale model references in CLAUDE.md files; MCP tool/WebFetch outputs now emit to OpenTelemetry span events (`OTEL_LOG_TOOL_CONTENT=1`); and `attribution: false` in settings.json to hide commit attribution lines.
**Why it matters:** The model-locking controls address drift when Anthropic releases new model versions mid-sprint — you can pin Opus 5.5 for all team sessions until you've validated it on your stack.

### [Claude Code v2.1.277 — Falls Back to AGENTS.md](https://code.claude.com/docs/en/changelog)
When `CLAUDE.md` is absent, Claude Code now reads `AGENTS.md` as project instructions, improving interoperability with Codex CLI and other tools that use that convention.
**Why it matters:** If you work across Claude Code and Codex CLI on the same repo, you can maintain a single `AGENTS.md` and drop the duplicate `CLAUDE.md`.

### [Codex CLI v0.154.0 — GPT-6 Sol/Luna + Amazon Bedrock](https://github.com/openai/codex/releases)
The latest Codex CLI release adds GPT-6 Sol and Luna model support, Amazon Bedrock as an upstream provider with `/import` in remote sessions, a fullscreen TUI with transcript search and mouse selection, and a `/usage` analytics dashboard for token and plugin activity.
**Why it matters:** Amazon Bedrock support means Codex CLI can operate within AWS-governed environments — relevant if clients have data-residency constraints alongside Cloudflare Workers deployments.

## 🟡 Noteworthy

### [Cloudflare Worker Previews — Isolated Per-Change Environments](https://developers.cloudflare.com/changelog/post/2026-09-22-worker-previews/)
Worker Previews (September 22) let you spin up an isolated, production-like environment for each code change — its own URL, bindings, configuration, and observability, fully separated from production and from other Previews.
**Why it matters:** Testing Workers/Pages changes against a live-like environment before merging removes the "works in `wrangler dev` but breaks in prod" failure mode from your Cloudflare stack.

### [Workers KV Read Latency Improvements — Rolled Out to All Namespaces](https://developers.cloudflare.com/changelog/product/kv/)
Cloudflare completed a rollout of read-latency improvements across all KV namespaces; no action required from users.
**Why it matters:** Any KV-backed config, session, or feature-flag data in your Workers (including anything Bucktee uses for plugin licensing or state) gets faster reads for free.

### [Gemini CLI Deprecates Code Assist Tiers, Releases antigravity-preview-09-2026](https://releasebot.io/updates/google/gemini-cli)
Gemini CLI stopped serving Google AI Pro/Ultra and Code Assist for individuals as of June 18; September brings `antigravity-preview-09-2026`, deprecating the May preview. The OSS CLI (v0.62.0-nightly) ships MCP fixes and memory lifecycle improvements for long-running agent loops.
**Why it matters:** If teammates use Gemini CLI under Google AI Pro they need to migrate to Antigravity; the open-source CLI path remains stable for daily agentic use.

### [WooCommerce Wholesale Lead Capture — Critical RCE Actively Exploited (CVE-2026-27540)](https://www.infosecurity-magazine.com/news/woocommerce-wholesale-lead-capture/)
CVE-2026-27540 (CVSS 9.8) in the WooCommerce Wholesale Lead Capture plugin is under active exploitation — Wordfence blocked 100,000+ attempts as of September 14. Update to version 2.0.3.2 or later immediately.
**Why it matters:** Unauthenticated exploitation means any WooCommerce store running this plugin is exposed without a login attempt; flag any Bucktee-adjacent sites using it for emergency update.

### [WooCommerce Core: DoS (CVE in < 11.1.0) and SQL Injection (CVE in < 11.0)](https://wpscan.com/plugin/woocommerce/)
Two WooCommerce core CVEs published this month: an unauthenticated DoS (CVSS 7.5, fixed in 11.1.0) and a Shop Manager+ SQL injection (CVSS 6.8, fixed in 11.0).
**Why it matters:** Sites below WooCommerce 11.1.0 are exposed to no-auth DoS; update all WooCommerce installs in your plugin-client estate to 11.1.0.

## 🧠 Takeaways

- **Opus 5.5 is the new baseline for serious agentic work.** Cheaper than Opus 5, 1M context, Claude Code promotes it automatically. If cost has been holding back agentic usage, this week's price drop removes that constraint.
- **AGENTS.md interop is quietly significant.** Claude Code now reads the same instruction file as Codex CLI. One file across both tools reduces daily cognitive overhead when you switch between them.
- **Worker Previews changes the Cloudflare iteration loop.** Production-isolated URLs per change — not just `wrangler dev` — means Workers/Pages changes can get real integration testing before merging, matching the confidence level of traditional staging environments.
- **WooCommerce's attack surface expanded sharply this week.** Two core CVEs plus an actively-exploited CVSS 9.8 third-party plugin in one week is a pattern. Automated update checks for WooCommerce core and its ecosystem should be a standing item in the Bucktee maintenance runbook.
